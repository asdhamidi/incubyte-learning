# Reflection
When data transformation logic is created without test-first, it is usually all in one go - the entire transformation logic is developed in one iteration and the entire transformation logic sits together and gets executed together, as well.

What I feel that test-first improves is that it makes sure all the bases are covered and tested as we go along creating the logic, additionally, it makes sure the different rules/logic actually work together harmoniously, rather than competing with each other.

For me, it makes sure that all the bases are covered and tested as we go along, and each of them gets proper attention and "care". Also, as we increasingly add more test cases, the previous test cases also need to pass, hence it logic-level integration testing as well.
